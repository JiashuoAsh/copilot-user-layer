# 实验溯源与结果比较

跨项目行为规则。执行相关比较或代码检查前读取当前项目的评测协议、报告器实现和相关测试，以实际实现确认字段与支持范围；不假定语言、目录、指标或收据格式。本指令不授权修改、启动实验或重跑。

## 计算成本与比较目标

- 精度等性能为主目标时，计算成本要求透明且符合项目实际约束，不默认要求相等。允许候选采用不同的更新步数、模型容量、优化预算或计算量；不得仅因成本不同拒绝性能比较、淘汰候选或要求全部基线重跑。项目明确的延迟、显存、总预算及基准协议限制仍生效；没有等预算要求时不自行添加，允许额外计算不等于无限资源授权。
- 根据比较目的选择控制：比较可行方案的精度时报告各自配置与代价；声称等预算优势或效率优势时，采用相应的预算控制和成本测量；将收益归因于特定机制而需排除额外容量或计算时，补有针对性的匹配对照。性能改善与机制成立分别判断，机制尚未确认不妨碍保留已验证的性能收益。
- 同条件任务性能比较不意味着所有方法配置与成本相同：按项目合同核对数据、信息可用性、计分及模型选择规则，方法预算差异明确列出，不冒充等预算或单因素因果比较。允许更多计算不能换取禁用标签、未来样本或其他协议禁止的信息。
- 按当前结论需要记录相关的更新步数、耗时、显存、模型规模或 FLOPs，不强制每次测全套；未测项标明未知，不能推定成本相等或更高效。区分方法运行成本与调参搜索成本，说明配置选择及重要投入差异；采用可靠的已发表配置或合理调优的基线，不用明显未调好的基线夸大优势。
- 候选及超参数在协议允许的开发数据上选择；最终保留评估不反复用于调参或挑方案。筛选结果与完整确认分开，重复次数根据波动和运行成本决定，不只挑最好的一次。协议、数据划分、主指标或选择规则确需改变时另记版本与可比较范围，不能为了涨点漂移判据。

## 区分 Hash 的用途

校验开销与证据复用按下一节处理；保留输入绑定和收据完整性不等于每次重新扫描全部输入或重跑模型。

- **代码来源**：代码 hash 追溯产生结果的代码快照，不是跨运行比较的相等门槛。候选之间、候选与参考之间可使用不同代码 hash；不得仅因此拒绝报告、否定历史结果或要求重跑旧基线。hash 不同不能证明算法或计分发生变化，hash 相同也不证明评测公平。
- **输入绑定**：同条件比较核对协议、数据及划分、checkpoint、样本/帧选择、索引与顺序等项目相关条件。保留实际输入绑定校验；不匹配时调查差异，不改写收据或关闭校验来伪装同条件比较。不同协议或输入条件的结果分开标注；在解释限制后可作描述性比较，不能宣称同条件或单因素归因。不同方法允许的预训练来源或 checkpoint 差异按评测合同判断，不机械要求所有方法 checkpoint 相同。
- **方法配置**：各 run 保留自己的方法标识、配置及可用的配置 hash，不要求不同方法的配置 hash 相同。precision、超参数和实现差异随比较说明；判断公平性时核对项目合同。
- **收据完整性**：保留项目已有的 hash 格式、成功状态、真实计算/计分、任务/样本/步骤覆盖和指标算术一致性等适用检查。允许代码 hash 不同不等于允许损坏、缺失或未完成的记录冒充完整报告。部分运行只能明确标为部分结果。

## 校验开销与证据复用

- 校验服务于本次动作和结论。启动前只完成会影响本次安全执行、输入与计分有效性的必要检查；初筛采用最小相关测试或烟测，不默认追加全套回归、完整数据遍历、全部基线复跑和重复推理。已有等价检查或实际运行已覆盖的路径，不再单独重复做同一烟测。筛选证据仍标为筛选，不能冒充完整确认。
- 同一相关代码、输入、协议与环境版本下已通过且可追溯的校验，由父级和执行者共享复用；不因换角色、换会话或汇总报告重复执行。只对变化及真实依赖补增量检查；数据处理、标签映射、样本覆盖、计分、预测/更新时序等关键路径改变，或出现失败、矛盾、损坏迹象时，重开受影响校验，必要时扩大范围。项目强制检查和未解决的有意义失败不能以节省开销为由跳过。
- 大数据、checkpoint 和固定快照优先引用已核验的内容指纹、可信版本清单与校验结果，避免每个 run/检查者重复读取、哈希或复制同一份内容。复用须能确认绑定到当前实际输入及校验器版本，依靠不可变存储或可靠的变更检测；文件名、路径、大小或 mtime 单独不构成内容未变的证明。首次、可变输入无法确认未变、校验器相关逻辑变化或有损坏迹象时，重新核验受影响内容，不伪造或关闭绑定检查。
- 完整确认和正式报告前，补齐本次结论所需的覆盖、完成状态、指标及比较有效性检查；优先使用原始运行产物和已有可复用证据，不为补检查默认再跑训练/推理或所有基线。仅当现有产物不能回答影响结论的缺口时，安排针对性重算或重跑；未验证的范围明确保留，不能因此宣称完整通过。
- 校验明显挤占主实验时，先利用已有日志、工具统计或低成本计时区分校验墙钟时间、GPU 计算与重复 I/O，报告主要开销和可复用项；不为计时重跑整批任务或另建重型审计系统。按主张与实际风险选择开销最小的有效检查，不设统一耗时比例，不把本节变成新的预算审批门槛。

## 比较与归因

1. 从原始运行记录和产物核对输入与完成状态，保留运行时记录的代码、配置及收据指纹；不以当前源码 hash 替换历史来源。缺少字段时报告证据缺口，不补造 hash 或推定完整。
2. 跨代码版本可报告指标与差值，并注明跨快照的描述性比较。将差值归因于某项方法改动前，检查实际代码、配置与评测链路差异；区分已核实事实与未知，不凭 hash 推断方法优劣。
3. 只有待排除的改动实际影响目标结论且现有证据不足时，才提出针对性验证或重跑；不因日常代码迭代默认要求全部基线重跑。所需范围由影响决定，执行遵循已有授权。
4. 历史收据和报告保持原样；新报告写入全新位置，不手工改数值或 hash。发现历史错误时另写更正和来源引用，不覆盖原始证据。

## 修改与交付

检查或修改评测/报告代码时，核对上述用途是否被混淆。修改逻辑后运行项目相关回归检查：不同代码 hash 的完整记录仍能报告并保留来源；输入绑定不匹配、不完整或计数/指标错误不能伪装成完整同条件结果。仅改指导文档时检查触发描述、引用与规则一致性；普通无关代码检查不触发实验重跑或 GPU 检查。
