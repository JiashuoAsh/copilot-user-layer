# 设计初步技术路线

## 开始前

实际读取[概念标准](../../research-guides/concepts.md)、[文献规则](../../research-guides/literature-rules.md)、[交互规则](../../research-guides/interaction-rules.md)和[项目记录规范](../../research-guides/project-records.md)。领域为多模态 continual TTA 时，再读取[CMTTA 指南](../../research-guides/domains/cmtta.md)。

可独立调用，也可由 `research-explore` 读取。接续已确定的问题、假设或探索目标，只补足会改变有效性的输入。每次新请求先调查相关文献与实验协议，再讨论；同轮已有有效调查时只补关键缺口。无法核查的数据或协议标为待确认。

## 工作流程

1. 从要区分的答案或解释反推所需证据，避免从现成工具和算法模块出发拼装路线。
2. 将每个核心问题或假设对应到观测、对照、干预或比较。说明竞争解释是否也能产生相同结果，以及缺少什么辨别证据。
3. 在研究构想粒度明确数据与协议要求、比较基线、测量与判读规则、关键混杂和可行性边界。研究不适合实验干预时采用相应的描述或分析设计。
4. 提出一个最小区分性验证：它能改变哪项判断、什么结果支持或削弱解释、哪些结果仍然无法下结论。必要时考虑跨流次序、随机性或不确定性，而非只比较一个平均分。
5. 不虚构数据集特性、可用标签、硬件预算或已有结果。资源缺口明确列出；汇报文献发现后按交互规则分批追问。

## 交付与停止

交付“问题/假设或探索目标 → 所需证据 → 初步验证 → 结果解释”的对应关系、最小验证、风险和下一步。仅在用户手动调用本技能、已选中 `research-explore`，或明确授权维护记录时，按项目记录规范落盘；自动发现本身不授权写入，否则提供待写入内容。

默认到可讨论的路线为止，不要求完整超参、可运行代码或排期；只有用户明确要求后才扩大到实施。阴性结果可以说明假设不成立，并不自动说明技术路线无效。
