# UI 原型分支

仅当问题是“界面应该长什么样/如何组织”时使用本参考。如果问题是逻辑或状态模型，改读 [`logic.md`](./logic.md)。

1. 先定义要比较的用户任务和关键差异，默认生成 3 个方案，最多 5 个。每个方案至少在布局、信息层级或主要交互模型上有实质差异；仅颜色或文案微调不是独立方案。
2. 优先把方案挂在已有页面的同一路由上，保留现有 data fetching、参数和 auth，只替换被评估的渲染子树。只有确实没有合理宿主时才创建 throwaway route，并遵循项目路由惯例、在路径或文件名中明确 prototype。
3. 在同一路由用 `?variant=` 选择方案，默认 `A`，未知值回退默认。提供共享的固定底部切换栏：上一个箭头、当前 key/名称、下一个箭头，循环切换；点击和 `←`/`→` 键更新 URL，使方案可分享且刷新稳定。输入框、textarea 或 `[contenteditable]` 聚焦时不要拦截方向键。切换栏必须明显区别于被评估的界面，并在 production build 中隐藏；检查实际构建配置，不假定环境变量门控已经足够。
4. 尽量复用项目组件库和数据读取，但不要共享会锁死方案结构的 layout 抽象。默认只读展示；变更操作使用 stub 或明确标注的临时状态，不触达生产数据。
5. 输出运行方式、宿主 URL、全部方案键、方案差异和待用户判断的问题。选定方案后记录理由、观察证据和局限；完整方案集合、切换栏和结论作为 primary source 留在 throwaway 分支或等价审计位置，正式实现需按项目质量标准重写和验证。
