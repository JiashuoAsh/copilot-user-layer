# 科研多 Agent 协作：讨论与决策归档

本文件保存 `research-agent-collaboration-plan.md` 历次整理前的用户评注、相关回应摘要和决定演变。它是追溯记录，不是运行指令；当前采用的方案以[总体规划](research-agent-collaboration-plan.md)为准。

## 使用说明

- 用户评注按原出现顺序逐字保留，包括 `> comment:`、`> user comment:` 和全角冒号写法。
- 历史回应按议题压缩为摘要，保留当前结论、替代关系和待审阅范围；不把摘要误写成逐字转录。
- 归档中的“当前结果”是迁移时的状态摘要；它不把历史建议改写成当时已经批准或已经部署。
- 正文使用 O01–O09、D01–D10 和 Q1–Q6 作为稳定索引；后续评论应追加到本文件对应议题下，并把新的当前结论同步到正文。
- “同意”“ok”等确认只在正文决策表明确记为已确认时才具有决策意义；单独的历史问句不构成授权。

## O03：端到端交接与 C 框架

### 原始评论

> user comment: 同意你的推荐。但是有个问题，我只看到了你的推荐，看不到“ A/B/C”具体指代什么方案。

> user comment: C，按照你的推荐：“以 C 作为完整框架，但允许简单任务走更短的调用路径”

### 相关回应与当前结果

讨论补充了 A/B/C 的含义，并将旧的“扩展 Research 为总负责人”的 B 方向替换为新 Agent 承担端到端责任。C 表示新端到端负责人组织必要工作线 Lead，同时允许简单任务直接交给合适的专家或执行者；它不要求三个 Lead 同时存在。

当前结果：C 框架、计划/验证和新端到端负责人方向已确认；具体角色、调用图、工具、执行授权和部署清单仍待审阅。详见总体规划 O03、阶段 2、D05–D06。

## O04：Research Ideation Partner 的专家协助与工具边界

### 原始评论

> user comment: 同意你的推荐。但尽量一次性把需要的工具都给他，避免在审查过程中频繁请求新增权限。我不知道我想的对不对：research-explore 是需要提供一个完整的研究思路的，那他在一定程度上是需要依赖 research agent的？为啥不让他调用 research agent啊？

### 相关回应与当前结果

讨论区分了“用户互动入口”“调用科学专家”和“接管实现/环境”三种能力。Research Ideation Partner 由用户启动，但启动后仍可向外委派调查；Research Investigation Coordinator 可作为按需的科学调查能力，不形成固定上下级。具体白名单、工具和通配路径必须在部署前核对。

当前结果：两个入口的调用方向已确认，但具体配置尚未部署。详见总体规划 O04、D03a、D03b、D04。

## O05：用户可选与 Agent 间调用

### 原始评论

> user comment: 同意你的推荐。Research 和 explore 都应该保持用户可选。但是是否也需要允许其他的agent调用？research 是专门做文献调研的啊？

> user comment: “调查协调器可以被其他 Agent 使用，构想伙伴仅由用户主动调用”

### 相关回应与当前结果

讨论明确了两个维度：`user-invocable` 表示用户入口，Agent 间调用则由运行时可见性和显式调用名单共同决定。调查协调器适合被其他 Agent 调用；构想伙伴保持用户主动启动，启动后可委派科学调查。

当前结果：上述调用原则已确认，具体调用名单、发现路径和运行时限制待审阅。不能只依赖目标 Agent 的开关推断“仅用户调用”。详见总体规划 O05、D02、D03a、D03b。

## O06：Debate 规则与独立 Moderator

### 原始评论

> user comment: 同意你的推荐。Debate 的现状确实需要澄清，避免重复和误导。但是我想让你评估一下 debate 的核心科学规则是否仍然适用，是否需要专门创建出一个工作流来？

> user comment: ok，我同意你的观点

### 相关回应与当前结果

讨论先检查了 Debate 的科学规则，再确认新增独立 `Debate Moderator`。保留按目标派工、先发现后审计、保留未决分歧、不按多数票判真以及证据足够即停止等规则；Moderator 只处理一个明确争议，按四项条件启动，组织独立判断和定向质询，不能改源码、启动实验或反向调用协调器与总负责人。

当前结果：独立角色及 O06 的触发、排除、交付和停止边界已确认；工具、模型、参与专家、预算、入口配置和部署仍待 D10 审阅。详见总体规划 O06、D06、D10 和 §6.1。

## O07：短任务与完整任务的报告深度

### 原始评论

> user comment: “短任务按问题返回，完整任务保留详细报告”

### 相关回应与当前结果

讨论接受了按任务范围适配输出的原则：短任务返回结论、依据、关键限制和下一步影响；完整任务保留角色需要的详细结构。不能为了短而省略与问题相关的状态、泄漏、公平性、竞争解释或判据检查。

当前结果：该原则已确认，并纳入阶段 1 修改包，不改变角色权限或验收范围。详见总体规划 O07 和 D04。
