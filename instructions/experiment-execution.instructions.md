# 实验执行与 GPU 调度

跨项目执行规则。先读取当前项目指令、运行协议、启动入口和输出目录约定；权限取当前任务与模式的有效授权，本指令不扩大权限，不要求重复批准已有授权。只检查代码时应用相关审查标准，不启动实验或查询无关 GPU。

## 持久运行与记录

- 长实验优先使用项目已有调度器或 `nohup` 等合适方式脱离交互终端；短时命令无需后台运行。不能将仅在当前终端后台运行等同于会话关闭后仍可靠执行；不适合脱离时说明具体限制。
- stdout/stderr 写入该 run 独占的持久日志，按项目约定放置；新运行/报告使用唯一输出，不覆盖历史证据。若入口要求输出目录不存在，不为日志预建该目录；先用独立启动日志，随后关联运行产物。
- 若通用终端规则要求覆盖工作区 `output.txt`，它仅作启动/检查命令摘要；实验原始输出始终保存到 run 日志，不让后续命令覆盖。并行任务各用独立日志和独占摘要路径或由父级串行汇总，不争写共享文件。
- 启动前记录命令、cwd、输入代码/config/数据与协议版本、环境、设备、唯一输出和日志位置；启动后记录主机、PID 加进程起始标识或调度器 job ID、启动时间及退出状态来源。重试前核对已有运行，缺报告不等于未启动。
- 启动后检查进程和初始日志，确认未立即失败；进程启动仅代表 running。完成须核对退出状态、必要产物与项目适用的完整性检查，不以最后一行日志或调用返回推定成功。失败尝试及原始输出保留，不记录秘密值。

## GPU 调度

- GPU 实验启动前检查 GPU 进程、显存占用和利用率，按实际空闲情况自行选卡；在授权范围内并行推进独立方法或 stream，不为常规选卡再询问用户。
- 并行数量仅依据 GPU 状态与预留规则，不以 CPU、主机内存或 I/O 检查/容量估算作为启动前置条件，不因预估不足减少并发或串行排队；实际发生相关故障后按证据诊断调整。
- 通常预留至少一张空闲 GPU，不固定卡号。仅当其余 GPU 均被他人占用且只剩一张空闲卡时，可在该卡启动一个实验；其他不满足预留条件的情况不新增占卡。不停止已有健康任务或他人进程腾卡；获授权处理本任务故障进程另按任务范围执行。
- 默认每卡一个 GPU 实验，不在同卡并跑多个 GPU 实验，包括训练、评估和推理；单实验多卡仅使用已有验证的兼容路径，不为强行并行更改正式 schedule 或引入未验证分布式路径。
- 同一有状态 continual stream 内的 task 按协议顺序执行，不为并行拆流、重置适配状态或改变预测/更新顺序。
- CPU-only 任务不经过 GPU 占用、预留或启动所有权门槛，仍保留授权、去重、固定输入、独占输出及退出证据。

## 状态检查

未收到完成/失败通知时，主动检查长任务至少间隔十五分钟；启动立即失败、用户查询或取消不受此间隔限制。使用已有完成通知/状态记录，不忙等。实验进程可持续不表示 Agent 常驻；返回运行身份、日志、当前状态和下一检查时间，没有可用监控机制就如实说明。
