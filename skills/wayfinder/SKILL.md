# 决策导航地图

Wayfinder 用于规划“目的地已知、路线仍有雾”的工作：多个相互依赖的未决问题会改变后续方案，且需要跨会话保存决策。单纯工作量大但方案清楚时，使用任务拆分方法，不建立决策地图。

## 规划步骤

1. **界定目的地。** 说明达到何种可观察状态即完成规划，例如形成已确认规格或选定方案。复用已有讨论和文件；不要把未回答的问题代替用户作答。
2. **找决策与依赖。** 广度扫描整个问题，分别记录已定结论、现在可精确提出的问题、尚未具体化的疑问和范围外事项。只有前一个答案确实影响后一个问题时才连依赖边。若路线已明确或问题足够小，一段话/普通任务拆分即可，不创建地图。
3. **逐步澄清。** 对需要用户判断的问题，提出有限、具体的澄清问题；可复用现有 `grill-me` 的工程参考作为提问方法，但不假设存在 Skill API，也不自动调用手动技能。需要外部事实时，仅在当前任务授权和工具能力允许时调查，并区分事实与建议。原型只在具体问题确实适合实验时使用。
4. **保持地图低冗余。** 确需地图时读取[地图模板](./assets/map-template.md)；为独立问题整理详情时读取[决策模板](./assets/decision-template.md)。地图索引已决定项及其引用、精确开放问题及其阻塞关系、尚未具体化、范围外。详细论证只保存在一个主文件/决策记录中，地图引用它。没有 tracker 时，获准保存可使用 `.scratch/<effort>/map.md` 和相邻 `decisions/NN-<slug>.md`；遵循项目已有约定。
5. **推进一个决策。** 每轮聚焦一个可解决的关键问题；答复后更新决策记录和受影响依赖。新问题只有变得可精确表述时才成为任务，不能预先虚构未来步骤。
6. **结束并交接路线。** 当目的地所需决定均已解决、剩余不确定性不再阻塞下一步时，停止规划；给出已确定路线、证据链接、剩余风险和后续可执行工作。实现工作仍由当前工程所有者完成。

## 权限边界

允许自动使用此规划方法不等于获准创建/更新文件、issue、远程 tracker、分支或推送。默认在对话中规划；只有用户要求保存或当前任务已有授权时才写入。外部发布或其他有副作用动作必须遵循明确的当前授权。尊重 Plan/Ask/Agent 模式及现有工具能力，不伪造执行或用户决策。

## 完成判据

目的地明确；已决策项有来源；开放问题有准确表述和真实依赖；粗略未知没有伪装成可执行任务；已明确何时停止规划并转入实施。文件写入时说明实际路径。
