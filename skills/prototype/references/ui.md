# UI 原型分支

仅当问题是“界面应该长什么样/如何组织”时使用本参考。

1. 先定义要比较的用户任务和关键差异；至少在布局、信息层级或交互模型上有实质差异。仅颜色/文案微调不是独立方案。
2. 尽量复用项目已存在的数据读取与页面框架，只替换被评估的界面部分；如果是新页面，遵循项目路由惯例。不要为原型引入不必要的架构。
3. 若用户需要亲自比较，可提供清晰切换机制；只有在项目框架允许且问题需要时才增加 URL 参数或键盘快捷键。原型控件应明显区别于正式界面。将临时路由/组件隔离在项目认可的 prototype-only 入口；在改动可能进入正式产物时检查 production build 或其配置，确认原型入口被排除。不要假定环境变量门控本身已足够。
4. 默认只读展示；变更操作使用 stub 或明确标注的临时状态，不触达生产数据。
5. 输出运行方式、方案差异和待用户判断的问题。选定方案后记录理由，并移除原型专用开关与未采用变体；正式实现需按项目质量标准验证。
