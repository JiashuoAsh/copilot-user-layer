# 项目研究记录

个人层保存通用方法和领域核查规则。项目中的问题、文献、候选假设、决定及实验构想只保存在该项目；不得从上一个项目暗带任务设定、数据集或结论。

## 先定位当前课题

1. 接续会话已确定的课题、用户显式路径和有效任务范围。检查项目指令、导航和记录内容；当前编辑文件、cwd 或工作区第一个目录只是线索，个人配置目录不自动是科研项目。
2. 区分代码库/worktree、当前课题记录入口、数据与运行产物位置。按当前动作需要确定即可；纯构想无需预先具备代码、数据、运行目录。不新增强制注册表或固定 schema，可在已有入口或协作记录中保存实际对应关系。
3. 唯一定位时直接复用，不重复询问；多课题或多代码库存在实质歧义时，只澄清会改变目标或写入对象的部分，继续独立只读工作。索引过期时核对实际文件，不凭目录名猜测。
4. 仅在确定是单一课题且无既有约定时，默认使用 `research/brief.md` 和 `research/evidence.md`。首次有实质内容时按需创建，不预建空模板。
5. `research/` 若是多课题容器，在已确定的课题下接续，例如 `research/topic-a/brief.md`；不在容器根部创建覆盖所有课题的默认 brief/evidence，不再自动嵌套 `research/`。已有 `notes/study-a/index.md` 等布局原位复用，不迁移或改名。目录用途不明或同名文件冲突时先核对。

读取必要入口后能明确当前课题、所用正文及本次动作范围，才进行依赖这些信息的写入。用户说“继续 topic-a”且材料足以唯一定位时直接推进。

## 文件职责与按需拆分

以下名称为无既有约定时的建议，不是自动发现机制或必建清单：

| 记录 | 内容与边界 |
|---|---|
| `brief.md` 或既有入口 | 当前研究焦点的简短摘要、当前最佳已验证方案的引用（适用时）、状态、有效正文链接、重要决定、未决项和下一步。早期可承载短构想；拆出 proposal 后以其当前焦点为准，只留摘要与链接 |
| `proposal.md` | 开头明确当前研究焦点，再展开科学论证主线及方法原理摘要，按[交付规范](proposal-delivery.md)组织；详细方法拆出后链接它，不复制完整公式或任务台账 |
| `method.md` 或独立 `methods/<method-id>.md` | 具体方法的唯一详细定义、假定、可用信息、符号、更新或推导、状态生命周期与边界；内容要求见交付规范 |
| `evidence.md` | 检索范围、日期、来源、阅读层级；主张与支持/挑战证据、定位、条件、局限及核查日期。区分来源主张与推断；实际结果引用原始运行，不复制日志或第二套指标数据 |
| `protocol.md` | 可执行的比较、对照、数据/划分、信息可用性、评价时序、指标与结果判读；无实验需要的研究不强建实验协议 |
| `implementation.md` | 方法/协议到代码的映射、接口、状态、关键配置与环境约束、正确性检查。源码与配置用链接引用，不复制全套易漂移参数 |
| `orchestration.md` 或既有任务系统 | 依赖、输入版本、范围、所有权、运行引用、验收状态；不代替科学方案与协议 |
| 既有运行产物目录 | 固定输入、命令、配置、日志、退出证据与原始指标；每次 run 明确课题与版本，位置沿用项目约定 |

短笔记先原位接续。构想需独立阅读或评论时再拆 proposal；方法出现较多公式、步骤、状态或需跨工作线独立交付时再拆 method；实际进入实现、实验或协作时再创建对应记录。持久方法记录不能只留聊天；只读或讨论请求不允许落盘时提供待写内容并明确说明。

当前研究焦点的内容与续轮判断统一见[交付规范](proposal-delivery.md#当前研究焦点与续轮)。尚未拆出 proposal 时，在既有入口简记即可；拆出后由 proposal 维护详细焦点，brief 引用它，不另建 focus 文件。详细来源、方法和评价约定分别引用 evidence、method 和 protocol，不为聚焦复制正文或强建尚不需要的记录。

性能导向项目区分“当前研究焦点”“当前候选”和“当前最佳已验证方案”：在 brief 或既有入口引用后者的方法/config、协议版本、有效比较范围及原始结果/报告，不复制指标台账，也不新增 best 文件。尚无完整确认的改进时保留有效基线，无有效结果时明确暂无，不能把初筛领先者直接标成已验证最佳。按项目目标与确认依据决定是否替换，记录理由与收益/代价，保留前一方案及失败候选的证据；关键场景退化或不同协议的结果分别说明，不能以不可比的单个最高数值替换。机制解释未定不抹去成立的性能结果；改变主攻问题或采用新候选也不覆盖旧最佳记录。

多个方法有独立比较与演化需要时使用既有 methods 布局或按需建立独立条目，由 proposal 链接当前采用项与必要候选，不再同时维护一份完整 method 副本，也不为每个短暂想法建文件。

拆分前读取源和目标，保留用户评论、稳定 ID、重要决定及历史；先写并回读核对，再将原位置改为摘要和链接，必要历史按 discussion 流程保存。每类当前正文只有一个权威位置，不覆盖无关笔记、不批量迁移。方法原理属于科学内容，类名与缓存路径属于实现；数据划分、可用信息和预测/更新顺序属于科学协议，不是随意可改的部署参数。

## 决策、证据和版本

重要问题、假设、方法和协议使用可追溯标识与 revision，链接依据；不要求逐句编号。决策状态与证据状态独立：候选、当前采用、已替代不等于已验证。记录实际决策者与理由，用户确认、Agent 建议及 Auto 自主采用分别说明。

同一课题内 ID 通过课题与文件定位，与其他课题的同名 ID 区分。上游改变保留旧决定和理由，只让真实依赖待复核或 stale；旧结果绑定原版本，不默默覆盖。拆文档、更换设备或日志路径本身不要求重跑实验。

## 写入与协作

用户手动调用阶段技能、选中 Research Explore，或要求维护记录时，可按任务范围更新已收敛记录；自动发现 Skill 本身不授予写入。用户要求只讨论、指定其他位置或只读时服从。记录维护本身不扩大到代码或训练；Research Run / Research Auto 执行模式读取[科研协作协议](orchestration.md)，Auto 启动明确课题自主推进后默认授权该课题研究闭环，不再逐项索权。

同课题 brief、proposal、method/methods、evidence、protocol、implementation 与 orchestration 的共享正文，由一个活动 root 集成；构想阶段无 root 时由当前课题记录维护者负责。Lead、专家与执行者返回建议或写分配的任务产物，不直接覆盖共享正文。并发第二会话先只读调查，确认所有权后再写；时间过期不证明原会话结束。

不同课题可独立维护记录，公共源码仍需按实际路径独占写者或隔离 worktree；公共输入默认只读、运行产物独占，不能因记录目录分开就假定代码无冲突。已有项目所有权规则先核对后接续。

## 更新与续接

在交互收敛或自主决策后及时保存事实、候选、变化原因和下一步，保持实际状态。写后重读片段和引用，确认未覆盖无关内容。新会话先定位当前课题并读取其 brief 或既有入口，再按链接核对当前研究焦点及必要方案、方法、协议和证据，说明本次接续的问题与下一步；不把候选列表当作全部待执行任务，也不把整套记录全部预载。
